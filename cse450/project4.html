Types and numeric expressions

Source type Wasm representation Meaning
double f64 64-bit floating point
int i32 Signed 32-bit integer
string i32 Byte offset of a NUL-terminated ASCII string in linear memory

An integer or hexadecimal literal now has type int; a literal containing a decimal point has type double. Underscore separators and the other Project 3 lexical rules remain. Integer literal magnitudes must be between 0 and 2147483647 (inclusive), including hexadecimal literals. Larger magnitudes are compile-time errors. A leading minus is a separate unary operator and does not extend the allowed literal range.

Runtime integer values still range from −2147483648 to 2147483647. The minimum value can be constructed as (-2147483647 - 1); no special literal handling is required.

int may be implicitly promoted to double in arithmetic, assignments, initializers, and returns. Do not implicitly narrow a double to an int. Check compatibility first, then actually emit the conversion where needed; accepting an assignment in the type checker does not convert its value.

function Example() : double {
  int count = 7;
  double result = count; // initializer needs i32 -> f64 conversion
  return result / 2.0;   // 3.5
}

For explicit numeric conversion, support int(expression) and double(expression). They have primary-expression precedence. Casting a type to itself is allowed and needs no conversion instruction. These casts do not accept strings; string(...) is not a cast in the core language.

Numeric arithmetic uses the operands’ common type: double if either operand is double, otherwise int. Consequently 5/2 is 2 while 5.0/2 is 2.5. Add % for signed integer remainder; it requires two ints.

Native Wasm numeric behavior

Use the native Wasm instructions below. Their runtime behavior is already implemented by the Wasm engine. Your compiler selects the instructions and inserts required conversions. You do not need to generate extra overflow, division-by-zero, NaN, infinity, or conversion-range checks, simulate these operations in C++, catch their traps, or turn runtime traps into compiler errors.

Source operation Emit Behavior supplied by Wasm
Int +, -, * i32.add, i32.sub, i32.mul Wrap modulo 2³²
Int unary -x i32.sub with operands 0, x Wrapping negation
Int / i32.div_s Truncate toward zero; trap on zero divisor or minimum int divided by −1
Int % i32.rem_s Remainder has the dividend’s sign; trap on zero divisor
Double +, -, *, /, unary - f64.add, f64.sub, f64.mul, f64.div, f64.neg Native floating-point results, including infinities and NaNs
int(double_value) i32.trunc_f64_s Truncate toward zero; trap on NaN, infinity, or an out-of-range truncated result
double(int_value) and implicit promotion f64.convert_i32_s Convert the signed int to double
Numeric comparisons Signed i32 comparisons or corresponding f64 comparisons Produce int 0 or 1

For example, int(-2.9) becomes −2 simply by using i32.trunc_f64_s. Use the signed forms (_s) for integer division, remainder, and ordered comparisons. Equality uses i32.eq/i32.ne. The behaviors above follow the Wasm numeric specification.

Compile-time checks for invalid literals and incompatible source types still belong in your compiler. The conditions and string rules below describe the additional lowering and supplied runtime helpers.

Comparisons and ! now return int 0 or 1. Their operands can still be int or double. Conditions still accept either numeric type: compare against zero, including for fractional doubles. Strings are not conditions. This preserves Project 3’s truth rule while introducing typed Boolean results. To lower conditions, compare ints with i32 zero or doubles with f64 zero; apply i32.eqz to the resulting truth value for !. This also handles fractional doubles and NaNs using ordinary Wasm comparisons.

Strings and character literals

A string literal uses double quotes. A character literal uses single quotes and represents an int ASCII code:

string greeting = "Hello";
int letter = 'A'; // 65

Both support \n, \t, \r, \", \', and \\. These escapes decode to one byte each. Other escapes, embedded NUL, raw newlines within literals, non-ASCII input, and character literals containing anything other than one decoded character are errors. "" is a valid empty string; '' is invalid.

Strings have value semantics:

  • Initializing or assigning a string variable copies the string’s bytes.
  • A string parameter has an independent value. The supplied parameter prologue copies strings passed from JavaScript before source code can mutate them.
  • A returned string must remain valid after the function returns. Its use must not expose mutable literal storage or a caller’s variable to unintended aliasing.
  • Concatenation and repetition produce new string values. Their left string operand is captured before evaluating the right operand: with s = "abc", s + (s[0] = 'X') produces "abcX", while s becomes "Xbc".
  • A literal occurrence must retain its original bytes across calls.
function Example() : string {
  string a = "abc";
  string b = a;
  b[0] = 'X';
  return a + b; // "abcXbc"
}

String-valued expressions are represented internally by pointers; copying is required at variable storage boundaries and at the host parameter boundary. Merely reading a variable for #s or s[i] need not allocate a copy. A simple correct approach also copies returned strings. Memory allocated for strings outlives the function that allocated it.

String operations

Expression Types Result
a + b string + string New concatenated string
a + c string + int Append the character with ASCII code c
a * n string * int Repeat a exactly n times
#a string Int character count, excluding NUL
a[i] string indexed by int Int ASCII code at index i
a[i] = c string variable indexed by int, assigned int Update one byte; expression returns c

String + int means a character, not decimal number formatting. "" + 65 is "A". Int + string and int * string are not supported. Comparisons, subtraction, division, and remainder are not defined for strings in the core.

Indexing binds more tightly than unary operators; #s is a length and #s[0] attempts to take the length of an int, which is an error. Read indexing may follow any string-valued primary, including a parenthesized expression. For indexed assignment, the base must be a string variable, optionally parenthesized. Assigning directly into a literal or concatenation result is an error.

Index bounds are 0 <= i < #s. Accessing the NUL terminator, a negative index, or another out-of-bounds index traps at runtime. Character stores and appended characters must be in 1..127; zero and non-ASCII values trap. A negative repetition count traps; repeating zero times produces an empty string.

These string checks are implemented in the supplied Runtime.hpp helpers. Use those helpers for checked indexing, character stores/appends, repetition, and allocation; you do not have to write those checks yourself. Wasm’s memory bounds checks alone do not enforce a string’s length. Your two student-written runtime routines are length and concatenation, described below.

For indexed assignment, evaluate the base, then the index and bounds check, then the right-side expression, once each. Preserve the computed address and assigned value rather than reevaluating the left side to obtain the expression’s result. If a bounds check traps, the right side does not execute.

Memory and the supplied runtime

Use NUL-terminated ASCII strings in Wasm linear memory. A string pointer is a byte offset represented by i32. Reserve address 0 for the empty string’s NUL byte. Put literal bytes in data segments, including their terminators, and start the heap after all literal storage. Escape bytes correctly in WAT; the provided WBytes helper can produce byte escapes.

The course runtime uses an allocation pointer that only moves forward. It starts with at least 16 pages and can grow to 256 pages (16 MiB). The supplied allocator checks allocation sizes and traps if it cannot allocate. There is no garbage collection or free; discard the module to reclaim its memory. A skipped string declaration initially refers to the empty string at address 0.

These exports form the interface used by both the browser and test runner:

Export Required behavior
memory The module’s linear memory
__alloc(size: i32) -> i32 Allocate size character bytes plus NUL; return the start offset
Each source function Use its exact source name and lowered signature
__heap Optional diagnostic export of the first unused byte

The host encodes string arguments using __alloc, writes ASCII bytes and the terminator, and decodes string results from memory. Do not reserve an undocumented fixed address range for host inputs. The host reacquires its memory view after allocation because memory growth can replace the buffer.

Runtime.hpp is supplied. It implements allocation, copying, character creation, repetition, bounds checking, and checked character stores. Its helpers include:

Internal function Parameters → result
$__alloc size → pointer
$__copy_bytes source, destination, byte count → no result
$__copy source pointer → new independent string pointer
$__char ASCII code → one-character string pointer
$__repeat string pointer, count → new string pointer
$__address string pointer, index → checked byte address
$__store_char byte address, ASCII value → stored value

You implement $__len and $__concat in StringRuntime.hpp. The starter contains trapping stubs with the required signatures. The supplied support functions call them, so completing them unlocks the rest of the runtime.

  • $__len(str: i32) -> i32: scan bytes until NUL and return the length.
  • $__concat(a: i32, b: i32) -> i32: find both lengths, allocate their sum, copy both sequences in order, and return the new pointer. The allocator supplies the final terminator.

The supplied module generator includes the runtime definitions, lays out literal strings, emits memory and heap definitions, and exports memory and __alloc. Students lower string expressions to the appropriate helpers and implement copying at assignments and returns. The supplied host-parameter prologue already protects the caller’s string buffer. You may replace the internal helpers if you preserve all language behavior and the required exported interface.

A complete text transformation

function Transform(string text) : string {
  int i = 0;
  while (i < #text) {
    int c = text[i];
    if (c >= 'a') {
      if (c <= 'z') text[i] = c - 'a' + 'A';
    }
    i = i + 1;
  }
  return text;
}

Transform("Hello!") returns "HELLO!". The caller’s original string remains unchanged. The playground expects a function taking one string and returning one string; its default name is Transform, but the name can be changed in the page. Each transformation loads a fresh instance to reclaim earlier allocations. The compiler itself must support all signatures in this specification, not just this viewer convention.
