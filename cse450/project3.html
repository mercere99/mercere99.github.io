Your first two projects executed programs directly. In this project, you will build your first compiler: a C++ program that translates a small numeric language, Strix, into WebAssembly Text (WAT). The supplied wat2wasm assembler converts that text into a WebAssembly binary that a browser can run.

From Marquee+ to Strix

You can reuse the ideas behind your Project 2 expressions, ASTs, scoped symbol table, conditionals, and loops. These are the deliberate language changes:

Marquee+ Strix in Project 3
Every value is a string Every source value is a double
Empty string is false; nonempty is true Zero is false; nonzero is true
Newlines terminate simple statements Semicolons terminate simple statements
Top-level statements execute in order A module contains named functions
SHOW and WAIT The host calls functions and observes their return values
Uppercase keywords Lowercase, case-sensitive keywords

Strings, durations, the clock, and string operators are not part of this project. There are no calls from one Strix function to another yet (those arrive in Project 4). JavaScript can call any exported function now.

Lexical rules

A supplied lexer.emplex and its generated lexer.hpp are included as a starting point. Use Emplex for your lexer; you may adapt these rules, but submit both files and keep them consistent. The same lexer reserves tokens for later projects; recognizing a token does not make that construct legal in this project.

  • Source files use ASCII. NULL or non-ASCII bytes are errors.
  • Identifiers match [a-zA-Z_][a-zA-Z0-9_]* and are case-sensitive. Names beginning with __ are reserved for the implementation.
  • Reserved words are function, double, int, string, void, if, else, while, break, continue, and return. Only double is a legal type here, but you’ll want to reserve the others for future projects.
  • Numeric literals are decimal integers (42, 1_000), hexadecimal integers (0x2A, 0xff), or decimals (3.5, 1_000.25). Single underscores may occur only between digits. Decimals need a digit on both sides of the period; .5, 5., exponent notation, and duration suffixes are not supported.
  • All numeric literals become double values in this project. Hex magnitudes must fit an unsigned 64-bit integer; decimal literals must convert to a finite double. A minus sign is an operator, not part of the literal.
  • Whitespace, including newlines, is ignored. // comments end at the newline. /* ... */ comments end at the first */ and do not nest. An unterminated block comment is an error.

Functions

function Add(double a, double b) : double {
  return a + b;
}

A program contains one or more function definitions. A function has a unique name, zero or more comma-separated typed parameters, a return type, and a braced body. Currently, parameters and returns must all be double. Functions can appear only at the top level, and nothing else may appear there in Project 3.

Export every source function under its original name. Functions do not execute when the compiler runs or when the module loads: the host invokes an export.

Each function body must end with a direct return expression; statement. Conditional early returns are allowed. We do not require a general analysis of whether every path returns or whether statements are reachable. Thus a function whose two if branches both return still needs a final return under this simple syntactic rule. Validate unreachable source code just like reachable code.

Parameters are local variables and may be assigned. Each call has its own parameter and local storage.

Statements and scope

statement → type ID "=" expression ";"
          | "if" "(" expression ")" statement ("else" statement)?
          | "while" "(" expression ")" statement
          | "return" expression ";"
          | "break" ";"
          | "continue" ";"
          | expression ";"
          | "{" statement* "}"
          | ";"

type is double. Declarations require initializers. Empty statements and empty nested blocks are allowed. else attaches to the nearest unmatched if. An expression statement discards its resulting value while preserving effects such as assignment.

Braces create lexical scopes. Parameters and declarations immediately inside a function’s outer braces share one scope. A name cannot be declared twice in the same scope; a nested block may shadow it. A declaration becomes visible after its initializer. This means:

function ScopeExample() : double {
  double x = 10;
  {
    double x = x + 1; // initializer reads the outer x; new inner x becomes 11
    x = 20;
  }
  return x;           // 10
}

A name outside its scope or before its declaration is an error. Function names and local-variable names use separate namespaces; duplicate function names remain errors.

Only braces introduce scopes. An unbraced declaration in an if or while body belongs to its surrounding scope. All local storage initially contains zero on each function call; executing a declaration evaluates its initializer. If control flow skips a declaration, its storage stays zero. A loop executes a body declaration’s initializer each time it reaches that declaration. Prefer braces around bodies containing declarations.

Conditions and loops

Zero (including “negative zero”) is false. Every other double is true, including fractional values, infinities, and NaN. Comparisons and ! produce 0.0 or 1.0. Convert truth by comparing a value with zero; do not truncate a double to an integer. Truncation would incorrectly make 0.5 false.

while rechecks its condition before each iteration. break exits the innermost enclosing loop. continue jumps to that loop’s condition. Both are errors outside a loop. return exits the entire function, including from inside nested blocks or loops.

function SumExceptThree(double limit) : double {
  double sum = 0;
  double i = 0;
  while (i < limit) {
    i = i + 1;
    if (i == 3) continue;
    sum = sum + i;
  }
  return sum;
}

SumExceptThree(5) returns 12 when called by the supplied host.

Expressions

Terminals are numeric literals, variable names, and parenthesized expressions. The following table lists precedence from strongest to weakest:

Operators Associativity Meaning
Unary -, ! Right Numeric negation; logical negation
*, / Left Multiplication; floating-point division
+, - Left Addition; subtraction
==, !=, <, <=, >, >= Non-associative Numeric comparison, producing a double 0 or 1
= Right Assign and return the stored value

All operands are evaluated left to right. Assignment evaluates its right side and stores the result in its left-side variable; that result is also the value of the assignment expression. Chained assignment therefore works. The left side must be a variable reference, optionally parenthesized.

a < b < c and a == b != c are errors. Parentheses explicitly permit a comparison result to participate in another comparison, such as (a < b) == 1.

Arithmetic follows WebAssembly f64 behavior; floating-point division by zero produces an infinity or NaN. Your compiler does not diagnose runtime numeric conditions. There is no integer remainder operator in Project 3.

Compiler organization

The starter provides a generated lexer, a command-line driver, numeric helpers, AST storage, and a scoped symbol table. These pieces are usable as supplied. Your main implementation work is in three files:

File Class and entry point Your work
Parser.hpp Parser::ParseProgram Read tokens, parse functions and expressions, resolve names, and build ASTs.
Semantics.hpp SemanticAnalyzer::AnalyzeProgram Visit the AST to check assignment targets, loop context, and required returns.
Translate.hpp WATTranslator::GenerateModule Visit expressions and statements, then return a complete WAT module.

The semantic and translation visitors include a completed number-literal case. Read START-HERE.md for the implementation order and each file’s header for its role, interfaces, and remaining work.

The starter uses ASTNode values with std::vector<ASTNode> children, following the DiceLang class example. Each node directly owns its subtrees; you do not need owning pointers or a separate allocation helper. ASTKind identifies the node’s operation, and AST.hpp documents the children in their required order. number_value holds a converted literal; variable_id identifies a resolved declaration. These fields are relevant only to the node kinds documented there. Because every Project 3 source value is a double, the scaffold has no type enum or expression-type annotations. Those can be added when multiple types arrive in Project 4.

The AST is data; visitors perform operations on it. A switch on ASTKind that dispatches to handlers is a suitable visitor implementation. Inspect nodes by reference, rather than copying subtrees during traversal. You may use a different class organization, but retain clear responsibilities for parsing, checking, and translation. Do not generate WAT as a side effect of parsing.

Resolve variable names to stable symbol IDs while parsing. A scope map can be popped without deleting the associated variable record. In generated WAT, each source declaration gets its own local ID even when two declarations share a source name. Declare all Wasm locals at the beginning of their function. The supplied SymbolTable manages one function at a time. Parameters and the outer function body share its initial scope; push/pop scopes for nested braced blocks. Resolve a declaration’s initializer before registering the new name, so a shadowing initializer can refer to the outer variable. Keep IDs rather than references to vector elements that could move as the program is built.

Useful stack contracts:

  • An expression leaves exactly one value on the operand stack.
  • A statement leaves no value. Use drop for an unused expression result.
  • An assignment expression can use local.tee to store and retain its value.
  • An if or br_if consumes an i32 condition. Source comparisons still produce doubles, so convert comparison results when used as source values.
  • A while needs an outer block for exit and an inner loop for repetition. Maintain a stack of loop labels so nested break and continue work.

For example, a complete WAT module for Add is:

(module
  (func $add (export "Add") (param $a f64) (param $b f64) (result f64)
    (f64.add (local.get $a) (local.get $b))
  )
)

Consult MDN’s text-format guide and the WABT tools when needed.

Errors

Report ERROR (line N): useful explanation on standard error, return 1, and leave standard output empty. Stop at the first error your implementation finds; we do not require a particular ordering among independent errors. Check:

  • Invalid characters, malformed literals, and unterminated comments.
  • Missing punctuation and any other invalid syntax.
  • Unsupported types or language features.
  • Unknown variables, duplicate declarations, and duplicate function names.
  • Illegal assignment targets and chained comparisons.
  • break or continue outside a loop.
  • Missing final returns and definitions in an invalid scope.

Exact message wording is not prescribed. Tests require a line number and a source diagnostic; a compiler crash or an unimplemented-feature placeholder is not an acceptable error report. Diagnostics should identify the actual problem. For an invalid character or an unknown variable reference, use the line where that character or identifier occurs, including after multiline comments.

Building, testing, and viewing your output

You need a C++20 compiler, Node.js 18 or newer, WABT (wat2wasm), and Python 3 for the local web server. No npm dependencies are required. The package README has setup instructions for macOS, Linux/WSL, and the course Linux systems.

make                  # builds Project3
make doctor           # checks Node and wat2wasm
make check-in         # runs the designated early tests
make tests            # compiles, assembles, AND executes all public cases
make examples         # compiles the supplied example programs
make serve            # starts a local server; Ctrl-C stops it

Open http://localhost:8000/web/ and click a module under Built examples. Start with growing-square.wasm, then press Play or move the time slider. Refresh list shows newly compiled programs, and Reload module fetches the selected example’s latest build. You can also choose a .wasm file from your computer; it loads immediately. You may choose the same file again, including after recompiling it.

make examples tries every example and lists successful builds even if other examples fail. It still returns failure if any example fails. This lets you try the growing square while loops or other advanced features are unfinished. Compiled files stay in build/examples; a generated index.json supplies the browser’s list. No files need to be copied into web/.

The Test results page displays the CLI report and can independently rerun compiled positive cases in the browser. Compilation errors are checked by the CLI, not by the browser.

The public suite contains 130 source fixtures, including positive cases with multiple calls and invalid programs. Expected behavior is in tests/manifest.json; tests are not comparisons against a particular WAT file. Logs and generated WAT/Wasm go in build/tests. Timeouts turn accidental infinite loops into failed tests. make tests returns a nonzero status if any case fails; missing tools also fail visibly.

The package includes tests/COVERAGE.md, which maps the public edge cases to the rules they exercise. Its case count measures coverage, not grading points; related failures may come from one underlying issue.

To compile your own example with the same pipeline:

node tools/course.mjs compile my_program.strix

The output is build/examples/my_program.wasm; click Refresh list to see it. Avoid using the same basename for two different custom programs, since the second would replace the first.

The image interface

function Shade(double x, double y, double time) : double {
    return (x + 1 < time / 10) * (y + 1 < time / 10);
}

This first animation needs only parameters, arithmetic, comparisons, and a return. Each comparison produces 0 or 1, so their product is 1 inside the square and 0 outside. At time 0 the image is black; over 20 seconds a white square grows from the bottom-left corner. Play repeats that interval; the slider lets you examine any time directly.

The viewer samples x and y in [-1,1], with positive y upward, and passes time in seconds. Return brightness in [0,1]; the viewer clamps finite values and displays non-finite values as black. All rendering occurs in a worker so Stop can terminate a bad loop. The viewer currently uses 160 × 160 samples.

After the growing square, try the gradient, moving rings, and Mandelbrot fractal. Every example is ordinary Strix input to your compiler. Shade is a viewer convention, not a language keyword or a required name in ordinary test programs.
